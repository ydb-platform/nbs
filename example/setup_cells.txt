5. Создать volume в каждой cell

Volume в cell-a:
./5-create_disk.sh \
    --cell cell-a \
    --kind ssd \
    --disk-id vol-a

Volume в cell-b:
./5-create_disk.sh \
    --cell cell-b \
    --kind ssd \
    --disk-id vol-b


Проверить владельцев:
./blockstore-client.sh describevolume \
    --host localhost \
    --port 9766 \
    --disk-id vol-a

./blockstore-client.sh describevolume \
    --host localhost \
    --port 9786 \
    --disk-id vol-b


6. Проверка cross-cell через NBD
vol-b принадлежит cell-b, но StartEndpoint будет отправлен в cell-a

./6-attach_disk.sh \
    --cell cell-a \
    --disk-id vol-b \
    --device /dev/nbd0

проверить запись/чтение
#sudo dd oflag=direct if=/dev/urandom of=/dev/nbd0 count=50 bs=4096
#sudo dd iflag=direct if=/dev/nbd0 of=./result.bin count=50 bs=4096

В списке должен присутствовать vol-b.
./blockstore-client.sh listendpoints \
    --host localhost \
    --port 9766

Проверить логи:
egrep  -n \
    'vol-b|CellId: "cell-b"|StartEndpoint|MountVolume' \
    logs/nbs.1.log \
    logs/nbs.2.log \
    | egrep -i DescribeVolume
В логе cell-b должен быть удалённый DescribeVolume:


Не должно быть:
egrep -n \
    'cell id mismatch|Describe timeout|Not all cells available' \
    logs/nbs.1.log \
    logs/nbs.2.log

// обратное направление

./6-attach_disk.sh \
    --cell cell-b \
    --disk-id vol-a \
    --device /dev/nbd1

Признак удалённого cells-запроса — поле Headers.CellId.


7. qemu (альтернатива ./6-attach_disk.sh)
Делается без ./6-attach_disk.sh
// !!! порты/аргументы ниже валидны пока qemu не поддерживает параметр cells (идет строго в cell-a)

После выхода из QEMU скрипт endpoint автоматически не останавливает.
Удалите его вручную:
./blockstore-client.sh stopendpoint \
    --host localhost \
    --port 9766 \
    --socket "$PWD/vol-b-vhost.sock"
